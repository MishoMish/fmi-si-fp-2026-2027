# Функции, среди и условни изрази

## Въведение

Миналата седмица дефинирахме първите си функции и видяхме общото правило за оценяване на комбинации. Тази седмица отговаряме на въпросите:

- **Какво точно се случва**, когато извикаме функция? (модел на заместването и модел на средите)
- Как да правим **разклонения**? (условни изрази и предикати)
- Как да **организираме** по-големи програми? (вложени дефиниции и блокова структура)

---

## 1. Дефиниране на функция

```
(define (<име> <параметър₁> ... <параметърₙ>)
  <тяло>)
```

- **Име** - символ, с който ще извикваме функцията
- **Формални параметри** - имена, използвани в тялото за аргументите
- **Тяло** - израз (или поредица от изрази), чиято стойност е резултатът

```scheme
(define (square x) (* x x))
(define (sum-of-squares x y) (+ (square x) (square y)))
(define (f a) (sum-of-squares (+ a 1) (* a 2)))
```

> 💡 Тялото може да съдържа няколко израза - връща се стойността на **последния**. Това ще е полезно, когато използваме вложени дефиниции.

---

## 2. Обръщение към функция: модел на заместването

**Обръщение** (извикване, прилагане) към функция: `(f 5)`.

**Модел на заместването** (substitution model) за прилагане на съставна функция:

> Оцени тялото на функцията, като всеки формален параметър е **заместен** със съответния аргумент.

### Апликативен ред (applicative order)

„Първо оцени аргументите, после замести“ - така работи Scheme:

```scheme
(f 5)
(sum-of-squares (+ 5 1) (* 5 2))
(sum-of-squares 6 10)              ; аргументите се оценяват ПРЕДИ заместването
(+ (square 6) (square 10))
(+ (* 6 6) (* 10 10))
(+ 36 100)
136
```

### Нормален ред (normal order)

„Първо замести всичко (без да оценяваш), оцени чак накрая“:

```scheme
(f 5)
(sum-of-squares (+ 5 1) (* 5 2))
(+ (square (+ 5 1)) (square (* 5 2)))
(+ (* (+ 5 1) (+ 5 1)) (* (* 5 2) (* 5 2)))   ; пълно разгръщане
(+ (* 6 6) (* 10 10))                          ; (+ 5 1) се оценява ДВА пъти!
(+ 36 100)
136
```

| Ред          | Кога се оценяват аргументите    | Езици                       |
| ------------ | ------------------------------- | --------------------------- |
| Апликативен  | Преди прилагането (веднъж)      | Scheme, C, Java, Python     |
| Нормален     | Когато са нужни (може многократно) | λ-смятане                 |
| Мързелив     | Когато са нужни, **веднъж**     | Haskell (Седмица 11)        |

> 💡 Когато и двата реда завършват, те дават **еднакъв** резултат. Но има програми, при които само нормалният ред завършва (вижте Пример 3).

## 3. Условни изрази

### `if`

```scheme
(if <условие> <следствие> <алтернатива>)
```

```scheme
(define (abs x)
  (if (< x 0) (- x) x))
```

`if` е **специална форма**: оценява се условието, след което се оценява **само единият** клон.

```scheme
(if (= 1 1) 42 (/ 1 0))   ; → 42 - делението на 0 никога не се оценява
```

> ⚠️ В Racket `else` клонът на `if` е **задължителен**: `(if #t 1)` дава грешка `if: missing an "else" expression`.

### `cond`

За повече от два случая:

```scheme
(cond (<условие₁> <израз₁>)
      (<условие₂> <израз₂>)
      ...
      (else <израз>))
```

Клаузите се проверяват **отгоре надолу**; оценява се изразът на **първата** клауза с вярно условие.

```scheme
(define (sign x)
  (cond ((> x 0) 1)
        ((= x 0) 0)
        (else -1)))
```

> ⚠️ Ако никое условие не е вярно и няма `else`, резултатът е специалната стойност `#<void>`. Винаги слагайте `else`!

### Логически операции: `and`, `or`, `not`

```scheme
(and <e₁> ... <eₙ>)   ; оценява отляво надясно, спира при първото #f
(or  <e₁> ... <eₙ>)   ; оценява отляво надясно, спира при първото не-#f
(not <e>)             ; обикновена функция
```

`and` и `or` са **специални форми** - те **не** оценяват всички аргументи (short-circuit):

```scheme
(and #f (/ 1 0))    ; → #f   (делението не се оценява)
(and 1 2)           ; → 2    (връща последната стойност!)
(or #f 3)           ; → 3    (връща първата не-#f стойност)
(and)               ; → #t
(or)                ; → #f
```

> 💡 Тъй като **всичко освен `#f`** е истина, `and` и `or` връщат не само `#t`/`#f`, а произволни стойности.

## 4. Предикати

**Предикат** е функция, която връща булева стойност. По конвенция имената им завършват на `?`.

| Предикат                                  | Проверява                        |
| ----------------------------------------- | -------------------------------- |
| `zero?`, `positive?`, `negative?`         | Знак на число                    |
| `even?`, `odd?`                           | Четност                          |
| `number?`, `integer?`, `rational?`, `exact?` | Вид на числото                |
| `boolean?`, `string?`, `symbol?`, `procedure?` | Тип на стойността           |
| `=`, `<`, `>`, `<=`, `>=`                 | Сравнение на числа               |
| `eq?`, `eqv?`, `equal?`                   | Равенство на произволни стойности |

### Видове равенство

```scheme
(= 1 1.0)          ; → #t   числово равенство
(eqv? 1 1.0)       ; → #f   различни видове числа
(eq? 'a 'a)        ; → #t   един и същ символ
(equal? "ab" "ab") ; → #t   структурно равенство
```

> 💡 Правило: числа сравняваме с `=`, символи с `eq?`, всичко останало (низове, списъци) с `equal?`. Ще се върнем на това в Седмица 4.

Можем да дефинираме собствени предикати:

```scheme
(define (divides? d n) (= (remainder n d) 0))
(define (leap-year? y)
  (or (and (divides? 4 y) (not (divides? 100 y)))
      (divides? 400 y)))
```

## 5. Функциите като абстракции

Пример: корен квадратен по **метода на Нютон**. Ако `guess` е приближение на $\sqrt{x}$, по-добро приближение е средното на `guess` и `x/guess`.

```scheme
(define (sqrt-iter guess x)
  (if (good-enough? guess x)
      guess
      (sqrt-iter (improve guess x) x)))

(define (improve guess x) (average guess (/ x guess)))
(define (average a b) (/ (+ a b) 2))
(define (good-enough? guess x) (< (abs (- (square guess) x)) 0.001))

(define (my-sqrt x) (sqrt-iter 1.0 x))
```

Задачата е **разбита на подзадачи**, всяка решена от отделна функция. Всяка функция е **черна кутия**: за да използваме `good-enough?`, ни е нужно да знаем **какво** прави, а не **как**.

### Свързани и свободни имена

```scheme
(define (square x) (* x x))
```

- `x` е **свързано** (bound) име - формален параметър. Името му няма значение: `(define (square y) (* y y))` е същата функция.
- `*` е **свободно** (free) име - стойността му идва отвън.

**Обхват** (scope) на свързаното име е тялото на функцията.

---

## 6. Вложени дефиниции и блокова структура

Помощните функции `sqrt-iter`, `improve`, `good-enough?` **замърсяват** глобалното пространство от имена. Можем да ги скрием **вътре** в `my-sqrt`:

```scheme
(define (my-sqrt x)
  (define (good-enough? guess)
    (< (abs (- (square guess) x)) 0.001))
  (define (improve guess)
    (average guess (/ x guess)))
  (define (sqrt-iter guess)
    (if (good-enough? guess)
        guess
        (sqrt-iter (improve guess))))
  (sqrt-iter 1.0))
```

Това е **блокова структура**. Забележете, че вложените функции **не приемат `x`** като параметър - те го „виждат“, защото са дефинирани в тялото на `my-sqrt`.

**Лексикален (статичен) обхват**: свободните имена във функция се търсят в средата, в която функцията е **дефинирана** (а не в която е извикана).

> 💡 Вложените `define`-и трябва да са **в началото** на тялото, преди израза, който връща резултата.

## 7. Модел на средите

Моделът на заместването е полезен, но **не** описва как наистина работи интерпретаторът и спира да е валиден, щом имаме присвояване (`set!`). По-точен е **моделът на средите** (environment model).

### Понятия

- **Свързване** (binding) - двойка `име → стойност`
- **Рамка** (frame) - таблица от свързвания
- **Среда** (environment) - **последователност от рамки**; всяка рамка (без глобалната) има указател към **обхващаща** (enclosing) рамка
- **Глобална среда** - съдържа вградените функции и дефинициите от най-горно ниво

**Стойност на име** в дадена среда: търси се в първата рамка; ако го няма - в обхващащата и т.н. Ако го няма никъде - грешка `undefined`.

### Функцията като обект

Оценяването на `(define (square x) (* x x))` създава **функционален обект** - двойка от:

1. **код**: параметри `(x)` и тяло `(* x x)`
2. **указател към средата**, в която е създаден

```
Глобална среда
┌──────────────────────────────┐
│ square: ─────────┐           │
│ +, *, ...        │           │
└──────────────────│───────────┘
                   ▼          ▲
                 [ ● | ● ]────┘
                   │
                   ▼
           параметри: x
           тяло: (* x x)
```

### Прилагане на функция

За да приложим функционален обект към аргументи:

1. Създаваме **нова рамка**, в която параметрите са свързани с аргументите
2. Обхващащата рамка на новата е **средата от функционалния обект** (не средата на извикване!)
3. Оценяваме тялото в новата среда

```scheme
(square 5)
```

```
Глобална среда  ┌───────────────────────┐
                │ square: ...           │
                └───────────────────────┘
                           ▲
                 E1 ┌──────┴──────┐
                    │ x: 5        │     тялото (* x x) се оценява в E1
                    └─────────────┘     → x се намира в E1, * - в глобалната
```

> 💡 Точно т.2 реализира **лексикалния обхват**: вложените функции в `my-sqrt` сочат към рамката на `my-sqrt`, в която е `x`.

## 8. Формално: правилата на модела на средите

1. **Константа** - стойността е самата константа.
2. **Име** - стойността от първата рамка в средата, която съдържа свързване за него.
3. **`(define <име> <израз>)`** - оценява `<израз>` в текущата среда и добавя свързване в **първата** рамка на средата.
4. **`(lambda ...)` / `(define (f ...) ...)`** - създава функционален обект с указател към **текущата** среда.
5. **Комбинация** - оценяват се всички подизрази; ако операторът е:
   - **примитивна** функция - прилага се директно;
   - **съставна** функция - създава се нова рамка (т.2 от „Прилагане“), чиято обхващаща среда е средата на функционалния обект; тялото се оценява в новата среда.
6. **Специални форми** (`if`, `cond`, `and`, `or`) - по собствените си правила.

> ⚠️ Моделите са **абстракции** - начин да разсъждаваме за програмите. Истинските интерпретатори използват различни оптимизации, но поведението им е същото.

## Обобщение

| Концепция               | Описание                                                       |
| ----------------------- | -------------------------------------------------------------- |
| Модел на заместването   | Заместваме параметрите с аргументите в тялото                  |
| Апликативен ред         | Аргументите се оценяват преди прилагането (Scheme)             |
| Нормален ред            | Аргументите се оценяват при нужда, евентуално многократно      |
| `if`, `cond`            | Условни специални форми - оценяват само нужния клон            |
| `and`, `or`             | Short-circuit; връщат стойности, не само `#t`/`#f`             |
| Предикат                | Функция, връщаща булева стойност; име, завършващо на `?`       |
| `=`, `eq?`, `equal?`    | Числово, идентично, структурно равенство                       |
| Блокова структура       | Вложени дефиниции в тялото на функция                          |
| Лексикален обхват       | Свободните имена се търсят в средата на дефиниране             |
| Модел на средите        | Рамки със свързвания, свързани в последователност              |
| Функционален обект      | Код + указател към средата на създаване                        |
