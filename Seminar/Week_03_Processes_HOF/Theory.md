# Процеси и функции от по-висок ред

## Въведение

Функцията е **локално** описание - как всяка стъпка се изгражда от предишната. **Процесът**, който тя генерира, е **глобалното** поведение - как изчислението се развива във времето и колко памет използва.

Тази седмица:

- Различаваме **рекурсивни** и **итеративни** процеси
- Използваме функции като **параметри** и като **резултати** - функции от по-висок ред
- Запознаваме се с **`lambda`** и **`let`**

---

## 1. Линейна рекурсия и итерация

### Линейно-рекурсивен процес

$n! = n \cdot (n-1)!$, $0! = 1$:

```scheme
(define (fact n)
  (if (= n 0)
      1
      (* n (fact (- n 1)))))
```

```scheme
(fact 4)
(* 4 (fact 3))
(* 4 (* 3 (fact 2)))
(* 4 (* 3 (* 2 (fact 1))))
(* 4 (* 3 (* 2 (* 1 (fact 0)))))    ; ← максимално разширение
(* 4 (* 3 (* 2 (* 1 1))))
(* 4 (* 3 (* 2 1)))
(* 4 (* 3 2))
(* 4 6)
24
```

Процесът първо се **разширява** (натрупват се **отложени операции** `*`), после се **свива**. Интерпретаторът трябва да помни веригата от отложени операции - паметта расте **линейно** с `n`.

### Линейно-итеративен процес

Друг подход: пазим **текущия резултат** в параметър-акумулатор.

```scheme
(define (fact-iter n)
  (define (iter i result)
    (if (> i n)
        result
        (iter (+ i 1) (* result i))))
  (iter 1 1))
```

```scheme
(fact-iter 4)
(iter 1 1)
(iter 2 1)
(iter 3 2)
(iter 4 6)
(iter 5 24)
24
```

Няма отложени операции! **Състоянието** на процеса се описва изцяло от стойностите на параметрите (`i`, `result`) - паметта е **константна**.

| Характеристика         | Рекурсивен процес          | Итеративен процес            |
| ---------------------- | -------------------------- | ---------------------------- |
| Отложени операции      | Да                         | Не                           |
| Памет                  | $\Theta(n)$                | $\Theta(1)$                  |
| Брой стъпки            | $\Theta(n)$                | $\Theta(n)$                  |
| Състояние              | Скрито в стека             | Явно - в параметрите         |

> ⚠️ **Рекурсивна функция** ≠ **рекурсивен процес**! `fact-iter` е рекурсивна функция (извиква себе си), но генерира **итеративен** процес.

### Опашкова рекурсия

Извикване е **опашково** (tail call), ако резултатът от него е директно резултат и на извикващата функция - нищо не остава „за после“. В `iter` рекурсивното извикване е опашково; в `fact` - не е (след него следва `*`).

Стандартът на Scheme **гарантира**, че опашковите извиквания не заемат допълнителна памет. Затова в Scheme нямаме нужда от цикли.

## 2. Дървовидна рекурсия

Числата на Фибоначи: $F_0 = 0$, $F_1 = 1$, $F_n = F_{n-1} + F_{n-2}$.

```scheme
(define (fib n)
  (cond ((= n 0) 0)
        ((= n 1) 1)
        (else (+ (fib (- n 1)) (fib (- n 2))))))
```

```
                    (fib 5)
                 /           \
           (fib 4)           (fib 3)
          /       \          /      \
     (fib 3)    (fib 2)  (fib 2)  (fib 1)
     /    \      /   \    /   \
 (fib 2) (fib 1) ...  ...  ...  ...
   ...
```

Всяко извикване разклонява на две - процесът е **дърво**. `(fib 3)` се пресмята **два пъти**, `(fib 2)` - три пъти...

- Брой стъпки: $\Theta(\varphi^n)$, където $\varphi = \frac{1 + \sqrt 5}{2} \approx 1.618$ - **експоненциален**
- Памет: $\Theta(n)$ - дълбочината на дървото

Итеративна версия - пазим две последователни числа:

```scheme
(define (fib-iter n)
  (define (iter a b count)
    (if (= count 0)
        a
        (iter b (+ a b) (- count 1))))
  (iter 0 1 n))
```

Стъпки: $\Theta(n)$. `(fib-iter 50)` → `12586269025` моментално, докато `(fib 50)` ще отнеме часове.

> 💡 Дървовидната рекурсия не е „лоша“ - понякога е най-естественото решение (обхождане на дървета, броене на начини). Но трябва да внимаваме за повтарящи се изчисления.

## 3. Порядък на нарастване

Казваме, че $R(n) = \Theta(f(n))$, ако съществуват константи $k_1, k_2 > 0$, независими от $n$, такива че за достатъчно голямо $n$:

$$k_1 f(n) \le R(n) \le k_2 f(n)$$

Пример - **бързо степенуване**:

$$b^n = \begin{cases} 1 & n = 0 \\ (b^{n/2})^2 & n \text{ четно} \\ b \cdot b^{n-1} & n \text{ нечетно} \end{cases}$$

```scheme
(define (fast-expt b n)
  (cond ((= n 0) 1)
        ((even? n) (square (fast-expt b (/ n 2))))
        (else (* b (fast-expt b (- n 1))))))
```

Стъпки: $\Theta(\log n)$ вместо $\Theta(n)$.

## 4. Функциите като параметри

Да сравним три функции:

```scheme
; 1 + 2 + ... + b
(define (sum-integers a b)
  (if (> a b) 0 (+ a (sum-integers (+ a 1) b))))

; 1³ + 2³ + ... + b³
(define (sum-cubes a b)
  (if (> a b) 0 (+ (cube a) (sum-cubes (+ a 1) b))))

; 1/(1·3) + 1/(5·7) + 1/(9·11) + ...   (→ π/8)
(define (pi-sum a b)
  (if (> a b) 0 (+ (/ 1.0 (* a (+ a 2))) (pi-sum (+ a 4) b))))
```

Те се различават само по **какво** сумират (`term`) и **как** преминават към следващия (`next`). Общият шаблон е математическото $\sum$:

```scheme
(define (sum term a next b)
  (if (> a b)
      0
      (+ (term a)
         (sum term (next a) next b))))
```

```scheme
(define (inc x) (+ x 1))
(define (sum-cubes a b) (sum cube a inc b))

> (sum-cubes 1 10)
3025
```

**Функция от по-висок ред** е функция, която приема функции като аргументи и/или връща функция като резултат.

### Обобщение: `accumulate`

Можем да абстрахираме и **операцията** (`+`) и **началната стойност** (`0`):

```scheme
(define (accumulate op null-value term a next b)
  (if (> a b)
      null-value
      (op (term a)
          (accumulate op null-value term (next a) next b))))

(define (sum term a next b) (accumulate + 0 term a next b))
(define (product term a next b) (accumulate * 1 term a next b))
(define (fact n) (product (lambda (x) x) 1 inc n))
```

> 💡 `accumulate` генерира рекурсивен процес. Итеративната версия `accumulate-i` натрупва резултата в `null-value`. Двете дават еднакъв резултат само ако `op` е **асоциативна**.

## 5. Ламбда изрази

Досадно е да дефинираме именувани функции като `inc` и `pi-term` само за да ги подадем като аргумент. **Ламбда изразът** създава **анонимна** функция:

```scheme
(lambda (<параметри>) <тяло>)
```

```scheme
(lambda (x) (+ x 4))
((lambda (x y) (+ x y)) 3 4)       ; → 7

(define (pi-sum a b)
  (sum (lambda (x) (/ 1.0 (* x (+ x 2))))
       a
       (lambda (x) (+ x 4))
       b))
```

> 💡 `(define (square x) (* x x))` е **синтактична захар** за `(define square (lambda (x) (* x x)))`. Функцията е стойност като всяка друга - `define` само ѝ дава име.

## 6. Локални дефиниции: `let`, `let*`, `letrec`

### `let`

```scheme
(let ((<име₁> <израз₁>)
      ...
      (<имеₙ> <изразₙ>))
  <тяло>)
```

```scheme
(define (f x y)
  (let ((a (+ 1 (* x y)))
        (b (- 1 y)))
    (+ (* x (square a)) (* y b) (* a b))))
```

`let` е синтактична захар за прилагане на ламбда:

```scheme
(let ((a 1) (b 2)) (+ a b))
; ≡
((lambda (a b) (+ a b)) 1 2)
```

Следствие: изразите `<изразᵢ>` се оценяват във **външната** среда - не виждат имената, въведени от същия `let`:

```scheme
(define x 2)
(let ((x 3)
      (y x))      ; тук x е външното - 2
  (* x y))        ; → 6
```

### `let*`

Последователно свързване - всяко следващо име вижда предишните:

```scheme
(let* ((x 3)
       (y (* x 2)))
  (+ x y))        ; → 9
```

`let*` е еквивалентен на вложени `let`-ове.

### `letrec`

Позволява имената да се отнасят **едно към друго** (нужно за локални рекурсивни функции):

```scheme
(letrec ((even? (lambda (n) (if (= n 0) #t (odd? (- n 1)))))
         (odd?  (lambda (n) (if (= n 0) #f (even? (- n 1))))))
  (even? 10))     ; → #t
```

> 💡 Вложените `define`-и от Седмица 2 са еквивалентни на `letrec*`. В практиката използваме вложени `define` за функции и `let`/`let*` за стойности.

## 7. Функциите като върнати оценки

Функциите могат да **връщат функции**:

```scheme
(define (make-adder n)
  (lambda (x) (+ x n)))

(define add5 (make-adder 5))
> (add5 3)
8
```

Върнатата функция „помни“ `n` - това е **затваряне** (closure).

### Композиция и многократно прилагане

$(f \circ g)(x) = f(g(x))$:

```scheme
(define (compose f g)
  (lambda (x) (f (g x))))

> ((compose square inc) 6)
49
```

$f^n = f \circ f \circ \cdots \circ f$:

```scheme
(define (repeated f n)
  (if (= n 0)
      (lambda (x) x)
      (compose f (repeated f (- n 1)))))

> ((repeated square 2) 5)
625
```

### Производна

$Df(x) \approx \dfrac{f(x + dx) - f(x)}{dx}$ - производната е **функция**, която по функция връща функция:

```scheme
(define dx 0.00001)

(define (deriv f)
  (lambda (x) (/ (- (f (+ x dx)) (f x)) dx)))

> ((deriv cube) 5)
75.00014999664018
```

## 8. Формално: функциите като пълноправни обекти

Един обект е **пълноправен** (first-class), ако може:

1. да бъде **именуван** (свързан с име)
2. да бъде **подаден като аргумент** на функция
3. да бъде **върнат като резултат** от функция
4. да бъде **включен в структура от данни**

В Scheme функциите са пълноправни - в много императивни езици не са.

### Затваряне в модела на средите

```scheme
(define add5 (make-adder 5))
```

```
Глобална среда ┌──────────────────────────────┐
               │ make-adder: ...              │
               │ add5: ───────┐               │
               └──────────────│───────────────┘
                              │        ▲
                              │   E1 ┌─┴─────┐
                              │      │ n: 5  │  ← рамката от (make-adder 5)
                              │      └───────┘     НЕ изчезва!
                              ▼          ▲
                           [ ● | ● ]─────┘
                             │
                     параметри: x
                     тяло: (+ x n)
```

Функционалният обект `add5` сочи към `E1`, затова `E1` остава жива, след като `make-adder` е завършила. При `(add5 3)` се създава рамка `E2 = {x: 3}` с обхващаща `E1` - там се намира `n`.
