# Странични ефекти и вход/изход

## Въведение

Всички функции, които писахме в Haskell досега, са **чисти**: резултатът зависи само от аргументите, и няма **странични ефекти** - не четат вход, не печатат, не променят файлове. Но реалните програми **трябва** да правят тези неща.

Тази седмица:

- защо страничните ефекти са проблем за чист език
- как Haskell ги изолира чрез типа `IO`
- вход/изход, файлове, **ленив** вход/изход
- случайни числа и изключения

---

## 1. Проблемът

**Референциална прозрачност**: израз може да бъде заменен със стойността си, без да се промени смисълът на програмата. Ако `f 3 = 7`, навсякъде можем да пишем `7` вместо `f 3`.

Да предположим, че `getLine :: String` чете ред от клавиатурата:

```haskell
-- хипотетично!
twoLines = getLine ++ getLine
```

- Колко пъти се чете? Ако `getLine` е стойност, двете извиквания са **еднакви** - само веднъж?
- В какъв ред? Мързеливото оценяване не гарантира ред!

В Scheme това не е проблем - `(read-line)` просто се изпълнява, когато се оцени. В Haskell редът на оценяване е **непредсказуем**, затова страничните ефекти трябва да се третират по различен начин.

## 2. Типът `IO a`

`IO a` е **действие** (описание на изчисление със странични ефекти), което, когато се **изпълни**, произвежда стойност от тип `a`.

```haskell
getLine  :: IO String          -- действие, което дава String
putStrLn :: String -> IO ()    -- функция, която по низ дава действие
main     :: IO ()              -- главното действие на програмата
```

> 💡 `()` („unit“) е типът с единствена стойност `()`. `IO ()` е действие без интересен резултат - като `void` в C.

Ключови идеи:

- `getLine` **не е низ** - то е **рецепта** за получаване на низ. Можем да я подаваме, да я слагаме в списък, да я комбинираме.
- Действията се изпълняват **само** ако са част от `main` (или ги въведем в GHCi).
- От `IO String` **не можем** да „извадим“ `String` в чиста функция. Веднъж в `IO` - винаги в `IO`.

```haskell
actions :: [IO ()]
actions = [putStrLn "едно", putStrLn "две"]   -- нищо не се отпечатва!

main :: IO ()
main = sequence_ (reverse actions)            -- изпълняваме ги в обратен ред
```


## 3. `do`-нотация

`do` комбинира действия **последователно**:

```haskell
main :: IO ()
main = do
  putStrLn "Как се казваш?"
  name <- getLine                       -- изпълни getLine, резултатът се казва name
  let greeting = "Здравей, " ++ name    -- чисто свързване (без IO)
  putStrLn greeting
```

| Конструкция       | Значение                                                       |
| ----------------- | -------------------------------------------------------------- |
| `action`          | Изпълни действието, игнорирай резултата                        |
| `x <- action`     | Изпълни действието, свържи резултата с `x`                     |
| `let x = expr`    | Чисто свързване - `expr` **не** е действие                     |
| `return x`        | Действие, което **не прави нищо** и дава `x`                   |

Типът на `do` блока е типът на **последното** действие.

> ⚠️ `return` **не** прекъсва изпълнението (за разлика от C/Java)! То само „обвива“ стойност в `IO`. `do { return 1; putStrLn "още съм тук" }` отпечатва текста.

> ⚠️ Честа грешка: `let name = getLine` - тук `name :: IO String`, а не `String`. За резултата на действие използвайте `<-`.

### Разделяне на чисто и нечисто

Добрата практика е **колкото може повече** логика да е в чисти функции, а `IO` да е тънък слой отгоре:

```haskell
-- Чиста функция - лесна за тестване
process :: String -> String
process = unlines . map reverse . lines

main :: IO ()
main = do
  input <- getContents
  putStr (process input)
```

## 4. Основни операции

| Функция       | Тип                         | Описание                          |
| ------------- | --------------------------- | --------------------------------- |
| `putStr`      | `String -> IO ()`           | Печата без нов ред                |
| `putStrLn`    | `String -> IO ()`           | Печата с нов ред                  |
| `print`       | `Show a => a -> IO ()`      | `putStrLn . show`                 |
| `getLine`     | `IO String`                 | Чете ред                          |
| `readLn`      | `Read a => IO a`            | Чете ред и го парсва              |
| `getContents` | `IO String`                 | Целия вход (мързеливо!)           |
| `interact`    | `(String -> String) -> IO ()` | Входът минава през функция     |
| `readFile`    | `FilePath -> IO String`     | Чете файл (мързеливо!)            |
| `writeFile`   | `FilePath -> String -> IO ()` | Пише файл (презаписва)          |
| `appendFile`  | `FilePath -> String -> IO ()` | Добавя към файл                 |

### Комбинатори (`Control.Monad`)

| Функция      | Тип                                  | Описание                         |
| ------------ | ------------------------------------ | -------------------------------- |
| `mapM_`      | `(a -> IO b) -> [a] -> IO ()`        | Действие за всеки елемент        |
| `forM_`      | `[a] -> (a -> IO b) -> IO ()`        | Същото, с разменени аргументи    |
| `mapM`       | `(a -> IO b) -> [a] -> IO [b]`       | Събира резултатите               |
| `sequence_`  | `[IO a] -> IO ()`                    | Изпълнява списък от действия     |
| `replicateM` | `Int -> IO a -> IO [a]`              | Повтаря действие `n` пъти        |
| `when`       | `Bool -> IO () -> IO ()`             | Условно изпълнение               |
| `unless`     | `Bool -> IO () -> IO ()`             | Обратното на `when`              |

```haskell
import Control.Monad (forM_, replicateM, when)

main :: IO ()
main = do
  n <- readLn :: IO Int
  xs <- replicateM n readLn :: IO [Int]
  forM_ (zip [1 ..] xs) $ \(i, x) ->
    putStrLn (show i ++ ": " ++ show x)
  when (sum xs > 100) $ putStrLn "Голяма сума!"
```

### Компилиране и изпълнение

```bash
ghc -O2 Main.hs -o main     # компилира
./main < input.txt          # изпълнява с вход от файл
runghc Main.hs              # интерпретира без компилиране
```

> ⚠️ При компилирана програма изходът е **буфериран**. Ако печатате подкана с `putStr` (без нов ред) преди `getLine`, добавете `hSetBuffering stdout NoBuffering` от `System.IO` в началото на `main`.

## 5. Ленив вход и изход

`getContents` и `readFile` връщат низ **веднага**, но съдържанието му се чете **при нужда** - докато обработваме низа. Така програма може да обработва вход, по-голям от паметта, ред по ред.

```haskell
main :: IO ()
main = interact $ \input ->
  unlines (map (show . length) (lines input))
```

`interact f` ≡ `getContents >>= putStr . f`. Програмата отпечатва дължината на всеки ред **веднага** след като е въведен - не чака края на входа.

| Предимство                               | Недостатък                                         |
| ---------------------------------------- | -------------------------------------------------- |
| Елегантно - входът е обикновен `String`  | Кога точно става четенето е **непредсказуемо**     |
| Константна памет при поточна обработка   | Файлът е отворен, докато низът не се прочете целия |
| Композира се с чисти функции             | Грешките при четене се появяват „по-късно“         |

> ⚠️ Класически капан: `readFile` и след това `writeFile` върху **същия** файл. Файлът още не е прочетен (мързеливо!), а вече се опитваме да пишем → грешка `resource busy (file is locked)`. Решение: принудете прочитането (например `length content `seq` ...`) или пишете в друг файл.

## 6. Случайни числа

Чиста функция не може да връща различен резултат при всяко извикване. Затова случайните числа се получават чрез **генератор** - стойност, която описва състоянието на псевдослучайната редица.

Библиотеката е `System.Random` от пакета **`random`** (не е част от стандартната библиотека):

```bash
cabal install --lib random
```

### Чист подход: явен генератор

```haskell
import System.Random

randomR :: (Random a, RandomGen g) => (a, a) -> g -> (a, g)
mkStdGen :: Int -> StdGen        -- генератор от „семе“ (seed)
```

`randomR` връща число **и нов генератор** - следващото число трябва да се вземе с **новия**:

```haskell
threeDice :: StdGen -> (Int, Int, Int)
threeDice g0 = (a, b, c)
  where (a, g1) = randomR (1, 6) g0
        (b, g2) = randomR (1, 6) g1
        (c, _)  = randomR (1, 6) g2
```

Със същото семе резултатът е **винаги** същият - функцията е чиста! Удобно за тестове.

Благодарение на мързеливостта можем да вземем **безкраен** списък от случайни числа:

```haskell
randomRs :: (Random a, RandomGen g) => (a, a) -> g -> [a]

ghci> take 5 (randomRs (1, 6) (mkStdGen 42)) :: [Int]
```

### В `IO`: глобален генератор

```haskell
randomRIO :: Random a => (a, a) -> IO a     -- използва глобалния генератор

main :: IO ()
main = do
  n <- randomRIO (1, 100) :: IO Int
  print n                                    -- различно при всяко изпълнение
```

> 💡 `randomRIO` е в `IO`, защото **зависи от състоянието** (глобалния генератор) и го **променя** - точно страничните ефекти, които `IO` изолира.

## 7. Изключения

### Грешки в чист код

```haskell
error     :: String -> a       -- прекъсва изчислението със съобщение
undefined :: a
```

```haskell
myHead :: [a] -> a
myHead []    = error "myHead: празен списък"
myHead (x:_) = x
```

> 💡 Типът `a` означава, че `error` може да стои на място от **всякакъв** тип. Но `error` е груб инструмент - **предпочитайте** `Maybe` и `Either` (Седмица 10), които правят възможната грешка видима в типа.

### Изключения в `IO` (`Control.Exception`)

Изключенията могат да се **хващат** само в `IO`:

```haskell
import Control.Exception

catch    :: Exception e => IO a -> (e -> IO a) -> IO a
try      :: Exception e => IO a -> IO (Either e a)
evaluate :: a -> IO a          -- принуждава оценяване до WHNF в IO
throwIO  :: Exception e => e -> IO a
```

```haskell
safeReadFile :: FilePath -> IO (Either IOException String)
safeReadFile path = try (readFile path)

main :: IO ()
main = do
  result <- safeReadFile "missing.txt"
  case result of
    Left err      -> putStrLn ("Грешка: " ++ show err)
    Right content -> putStr content
```

> ⚠️ Заради мързеливостта `try (return (1 `div` 0))` **не** хваща нищо - делението се оценява по-късно, извън `try`. Използвайте `try (evaluate (1 `div` 0))`.

### Безопасно четене на числа

`read` хвърля изключение при невалиден вход. `readMaybe` от `Text.Read` връща `Maybe`:

```haskell
import Text.Read (readMaybe)

ghci> readMaybe "42" :: Maybe Int
Just 42
ghci> readMaybe "4x2" :: Maybe Int
Nothing
```

## 8. Формално: `IO` като трансформация на света

Един полезен (макар и опростен) модел: действието е **функция**, която приема „състоянието на света“ и връща резултат и **ново** състояние:

$$\texttt{IO a} \approx \texttt{World} \to (\texttt{a}, \texttt{World})$$

- `getLine` взима света, прочита ред (променяйки света) и връща низа и новия свят.
- Последователността в `do` **предава** света от едно действие на следващото - това фиксира **реда** на ефектите.
- Тъй като „светът“ не може да бъде копиран или използван два пъти, ефектите не могат да бъдат дублирани или пренаредени.

Така езикът остава **референциално прозрачен**: `getLine` е винаги **едно и също** действие (една и съща функция над света); различни са само резултатите от **изпълнението** му.

Комбинирането на действия има обща структура с `Maybe`, `Either` и списъците - това е структурата на **монада** (Седмица 14). Засега `do` е просто начин да подредим действия.

## Обобщение

| Концепция                 | Описание                                                   |
| ------------------------- | ---------------------------------------------------------- |
| Референциална прозрачност | Израз може да се замени със стойността си                  |
| `IO a`                    | Действие, което при изпълнение дава `a`                    |
| `main :: IO ()`           | Входна точка на програмата                                 |
| `do`, `<-`, `let`         | Последователност, резултат от действие, чисто свързване    |
| `return`                  | Обвива стойност; **не** прекъсва изпълнението              |
| `mapM_`, `forM_`, `when`  | Комбинатори за действия                                    |
| Ленив вход/изход          | `getContents`, `readFile`, `interact` - четене при нужда    |
| `System.Random`           | `mkStdGen`, `randomR`, `randomRs`, `randomRIO`             |
| `error`                   | Грешка в чист код - предпочитайте `Maybe`/`Either`         |
| `catch`, `try`, `evaluate`| Хващане на изключения в `IO`                               |
| `readMaybe`               | Безопасно парсване                                         |
| `IO` като `World -> (a, World)` | Модел, обясняващ реда на ефектите                   |
