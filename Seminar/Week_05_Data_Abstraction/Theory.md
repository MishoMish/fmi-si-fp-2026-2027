# Абстракция с данни

## Въведение

В Седмица 3 видяхме **функционална абстракция** - функцията е черна кутия, използваме я, без да знаем как е реализирана. Същата идея се прилага и за **данните**:

> **Абстракция с данни** - програмата, която **използва** данните, не зависи от начина, по който те са **представени**.

Връзката между двете части е малък набор от функции - **конструктори** и **селектори**.

---

## 1. Пример: рационални числа

Искаме да работим с дроби $\frac{n}{d}$. Да предположим, че **вече имаме**:

```scheme
(make-rat n d)   ; конструктор - създава дробта n/d
(numer x)        ; селектор - числителят на x
(denom x)        ; селектор - знаменателят на x
```

Тогава можем да напишем аритметиката, **без да знаем** как е представена дробта:

$$\frac{n_1}{d_1} + \frac{n_2}{d_2} = \frac{n_1 d_2 + n_2 d_1}{d_1 d_2} \qquad \frac{n_1}{d_1} \cdot \frac{n_2}{d_2} = \frac{n_1 n_2}{d_1 d_2}$$

```scheme
(define (add-rat x y)
  (make-rat (+ (* (numer x) (denom y)) (* (numer y) (denom x)))
            (* (denom x) (denom y))))

(define (mul-rat x y)
  (make-rat (* (numer x) (numer y))
            (* (denom x) (denom y))))

(define (equal-rat? x y)
  (= (* (numer x) (denom y))
     (* (numer y) (denom x))))
```

Това е стратегия **„отгоре надолу“** (wishful thinking): пишем кода, сякаш нужните функции съществуват, и ги реализираме по-късно.

### Представяне чрез двойки

```scheme
(define (make-rat n d)
  (let ((g (gcd n d)))
    (cons (/ n g) (/ d g))))     ; съкращаваме при създаване

(define (numer x) (car x))
(define (denom x) (cdr x))
```

```scheme
> (define one-half (make-rat 1 2))
> (define one-third (make-rat 1 3))
> (add-rat one-half one-third)
'(5 . 6)
```

> 💡 Racket вече има вградени рационални числа (`1/2`). Тук ги реализираме сами, защото са прост и ясен пример за абстракция.

## 2. Бариери на абстракцията

Програмата се разделя на **нива**. Всяко ниво използва само интерфейса на нивото под него:

```
┌──────────────────────────────────────────────────┐
│    Програми, които използват рационални числа    │
├──────────────────────────────────────────────────┤  ← add-rat  mul-rat  equal-rat?
│        Рационални числа като числа               │
├──────────────────────────────────────────────────┤  ← make-rat  numer  denom
│   Рационални числа като числител и знаменател    │
├──────────────────────────────────────────────────┤  ← cons  car  cdr
│           Рационални числа като двойки           │
├──────────────────────────────────────────────────┤
│         Реализация на двойките в езика           │
└──────────────────────────────────────────────────┘
```

Хоризонталните линии са **бариери на абстракцията**. Предимства:

- **Лесна промяна на представянето**: ако решим да съкращаваме дробите не при създаване, а при достъп, променяме само `make-rat`, `numer`, `denom` - нищо над бариерата.
- **По-лесно разбиране**: всяко ниво се разглежда независимо.
- **По-малко грешки**: никой не „бърка“ във вътрешността.

> ⚠️ Нарушение на бариерата е например `(car one-half)` в код, който използва рационални числа. Използвайте `(numer one-half)`!

## 3. Какво всъщност са данните?

Какво трябва да изпълняват `make-rat`, `numer`, `denom`? Единственото **изискване** е:

$$\frac{\texttt{(numer (make-rat n d))}}{\texttt{(denom (make-rat n d))}} = \frac{n}{d}$$

Данните се определят от **конструктори, селектори и условия**, на които те удовлетворяват.

За двойките условието е: `(car (cons x y)) = x` и `(cdr (cons x y)) = y`. Всяка реализация, удовлетворяваща това, е валидна - **дори без структури от данни**:

```scheme
(define (my-cons x y)
  (lambda (m)
    (cond ((= m 0) x)
          ((= m 1) y)
          (else (error "my-cons: invalid selector" m)))))

(define (my-car p) (p 0))
(define (my-cdr p) (p 1))
```

```scheme
> (my-car (my-cons 1 2))
1
> (my-cdr (my-cons 1 2))
2
```

Двойката е **функция** (затваряне), която „помни“ `x` и `y`. Този стил се нарича **предаване на съобщения** (message passing).

> 💡 Границата между „данни“ и „функции“ е по-размита, отколкото изглежда!

## 4. Йерархични данни: дървета

Чрез затвореността на `cons` можем да представяме **йерархични** структури.

### Двоично дърво като списък

Представяне: празното дърво е `'()`, а непразното - списък `(корен ляво-поддърво дясно-поддърво)`.

```scheme
(define empty-tree '())
(define (empty-tree? t) (null? t))
(define (make-tree root left right) (list root left right))
(define (root t) (car t))
(define (left t) (cadr t))
(define (right t) (caddr t))

(define (leaf x) (make-tree x empty-tree empty-tree))
```

```
        5
       / \
      3   8
     / \   \
    1   4   9
```

```scheme
(define t
  (make-tree 5
             (make-tree 3 (leaf 1) (leaf 4))
             (make-tree 8 empty-tree (leaf 9))))

> t
'(5 (3 (1 () ()) (4 () ())) (8 () (9 () ())))
```

Функциите над дървета използват **само** интерфейса:

```scheme
(define (tree-sum t)
  (if (empty-tree? t)
      0
      (+ (root t) (tree-sum (left t)) (tree-sum (right t)))))

(define (tree-height t)
  (if (empty-tree? t)
      0
      (+ 1 (max (tree-height (left t)) (tree-height (right t))))))
```

> 💡 Ако утре решим да представяме дърветата другояче (например с вектори), `tree-sum` и `tree-height` остават **непроменени**. В Седмица 6 ще продължим с двоични дървета за търсене и графи.

## 5. Символни данни

Със `quote` можем да работим със **символи** като данни. Класически пример - **символно диференциране**:

$$\frac{dc}{dx} = 0, \quad \frac{dx}{dx} = 1, \quad \frac{d(u + v)}{dx} = \frac{du}{dx} + \frac{dv}{dx}, \quad \frac{d(uv)}{dx} = u\frac{dv}{dx} + v\frac{du}{dx}$$

Отново пишем алгоритъма чрез **абстрактен** интерфейс за изрази:

```scheme
(define (deriv expr var)
  (cond ((number? expr) 0)
        ((variable? expr) (if (same-variable? expr var) 1 0))
        ((sum? expr)
         (make-sum (deriv (addend expr) var)
                   (deriv (augend expr) var)))
        ((product? expr)
         (make-sum (make-product (multiplier expr) (deriv (multiplicand expr) var))
                   (make-product (deriv (multiplier expr) var) (multiplicand expr))))
        (else (error "deriv: unknown expression" expr))))
```

Представяме изразите като префиксни списъци - `'(+ x 3)`, `'(* x y)`:

```scheme
(define (variable? e) (symbol? e))
(define (same-variable? a b) (and (variable? a) (variable? b) (eq? a b)))
(define (sum? e) (and (pair? e) (eq? (car e) '+)))
(define (addend e) (cadr e))
(define (augend e) (caddr e))
(define (product? e) (and (pair? e) (eq? (car e) '*)))
(define (multiplier e) (cadr e))
(define (multiplicand e) (caddr e))
```

Пълната реализация с опростяване на изразите е в примерите.

## 6. Структури в Racket

Racket предоставя `struct`, която **автоматично** създава конструктор, селектори и предикат:

```scheme
(struct point (x y) #:transparent)
```

създава:

- конструктор `(point x y)`
- селектори `(point-x p)`, `(point-y p)`
- предикат `(point? v)`

```scheme
> (define p (point 1 2))
> (point-x p)
1
> (point? p)
#t
> p
(point 1 2)
```

> 💡 `#:transparent` позволява стойността да се отпечатва и сравнява с `equal?`. `struct` е удобен, но **принципът е същият** - конструктори и селектори. В курса ще използваме предимно двойки и списъци, за да виждаме представянето явно.

## 7. Формално: абстрактен тип данни

**Абстрактен тип данни (АТД)** се задава чрез:

1. **Множество от стойности** (носител)
2. **Операции** - конструктори, селектори, предикати
3. **Аксиоми** - условия, които операциите удовлетворяват

**Пример - двойки:**

| Операция                  | Аксиома                         |
| ------------------------- | ------------------------------- |
| `cons : A × B → P`        | `(car (cons x y)) = x`          |
| `car : P → A`             | `(cdr (cons x y)) = y`          |
| `cdr : P → B`             | `(pair? (cons x y)) = #t`       |

**Реализация** на АТД е всяко представяне, при което аксиомите са изпълнени. Видяхме две реализации на двойките - вградената и чрез затваряния.

**Пример - рационални числа:** аксиомата е $\texttt{(numer (make-rat n d))} \cdot d = n \cdot \texttt{(denom (make-rat n d))}$ за $d \neq 0$.

> 💡 Същата идея в Haskell се реализира чрез **модули**, които крият конструкторите (Седмица 10).

## Обобщение

| Концепция                | Описание                                                  |
| ------------------------ | --------------------------------------------------------- |
| Абстракция с данни       | Използването е отделено от представянето                  |
| Конструктор / селектор   | Създава стойност / извлича част от нея                    |
| Бариера на абстракцията  | Граница между нива; всяко ниво използва само интерфейса   |
| „Wishful thinking“       | Пиши кода, сякаш нужните функции съществуват              |
| Двойки чрез затваряния   | Данните могат да са функции (message passing)             |
| Дървета чрез списъци     | `(корен ляво дясно)`, достъп само през интерфейса         |
| Символни данни           | `quote` + символи = данни (напр. изрази)                  |
| `struct`                 | Автоматични конструктор, селектори и предикат в Racket    |
| АТД                      | Стойности + операции + аксиоми                            |
